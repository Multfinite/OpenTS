# Архитектура домена `narrative`

## Устройство корпуса

| Каталог | Что | Уровень по умолчанию |
| --- | --- | --- |
| `world/core/` | жёсткие инварианты: физика, магия, правила существования | `core` |
| `world/<раздел>/` | сущности: страны, институты, биология, экономика | `setting` |
| `world/timeline/` | хронология и причинность | `setting` |
| `chapters/` | текст | `presentation` |
| `drafts/` | черновики, не канон | `non-canon` |

## Инварианты

| ID | Инвариант | Чем проверяется |
| --- | --- | --- |
| `NR-INV-01` | Факт `core` меняется только решением `NR-*` (`NR-POL-02`) | `check_decisions.py` + ревью |
| `NR-INV-02` | Секрет имеет носителя (`NR-POL-11`) | `lint_scopes.py` |
| `NR-INV-03` | Текст не меняет факты (`NR-POL-07`) | отчёт `prose-cleanup`: список фактов до/после |

## Модель доступа

Двухосевая: `role × prism` (`access.md`). Следствие для архитектуры: у одного и того же факта может быть несколько корректных изложений, и они не обязаны совпадать — они обязаны быть согласованы по источникам.

## Анти-паттерны

| Не делаем | Почему | Что вместо |
| --- | --- | --- |
| «Энциклопедия мира» в одном файле (`NR-POL-13`) | Не ревьюится, не проверяется | Одна сущность — один документ |
| Секрет без носителя (`NR-POL-11`) | Забытый секрет всплывает неожиданно | `known_by` или удаление |
| Реткон под сцену (`NR-POL-01`) | Ломает уже написанное | Явный конфликт и решение |
| Выравнивание речи персонажа (`NR-POL-08`) | Убивает голос | Голос персонажа — часть факта |
